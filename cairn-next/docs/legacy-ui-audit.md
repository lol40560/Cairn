# 기존 Cairn 화면·사용자 기능 조사

조사 기준: `afc09834c1f0ce206ab08ec042262c4955ea710c` (PR #5 병합 커밋). 참조 checkout: `../reference-cairn`. 이 문서는 실제 화면 구현, 연결된 preload API, 관련 상태·보조 로직을 읽어 작성했다. 기존 앱 실행·회귀 테스트는 이 조사에서 수행하지 않았으므로 **코드에 구현 경로가 있다는 판정과 실제 실행 검증 통과를 구분**한다. 원본 코드와 `.cairn` 데이터는 변경하지 않았다.

아래 `경로:줄`은 모두 기준 커밋 안의 위치다. 영구 소스 링크 기본 주소: [기준 커밋 소스](https://github.com/lol40560/Cairn/tree/afc09834c1f0ce206ab08ec042262c4955ea710c). 새 앱 열은 구현 완료 보고가 아니라 유지·추가할 범위와 인수 기준이다.

## 반드시 구분할 다섯 가지

1. **저장 단위 동기화와 글자 단위 공동 편집:** `FilesView.tsx:258–267`은 Monaco의 전체 문자열을 `saveProjectFile` IPC로 저장한다. `481–503`의 `onChange`는 React 버퍼와 dirty 표시를 변경한다. Yjs 문서나 원격 커서 바인딩은 없다. 새 앱의 Yjs 공동 편집은 신규 기능이다.
2. **최근 수정과 현재 편집:** `src/lib/collaboration.ts:3–7,29–61`의 표시 근거는 최근 5분 내 저장된 op다. 코드 주석도 실시간 커서·잠금이 아니라고 명시한다. Edit claim은 별도로 존재하지만, 최근 활동 표시는 현재 편집 상태를 증명하지 않는다.
3. **접속과 동기화 완료:** `src/lib/teamJoin.ts:25–47`은 backend 참가 성공 후 방 상태를 확정한다. `teamHealth.ts:8–21`의 상태는 접속자·재접속·마지막 활동 등이며 프로젝트 전체 revision/hash 수렴 ACK가 아니다. `README.md:169`도 전체 프로젝트 수렴 증명 부재를 밝힌다.
4. **AI 이름과 도구 검증:** `src/lib/collaboration.ts:18–26`은 작성자 문자열에 `cursor|claude|copilot|codex|chatgpt|gemini`가 있는지 검사해 AI로 분류한다. 인증된 도구 연동 증거가 아니며 동명의 사람이 오분류될 수 있다. 새 앱에서는 선언/인증 연동/Unknown을 별도 provenance로 기록한다.
5. **Checkpoint 복원과 session rollback:** checkpoint UI는 비교, current revision, 미저장 파일 검사, 보호 checkpoint를 동반한 복원 API에 연결된다(`CheckpointsView.tsx:74–104`, `electron/main.ts:1110–1124`). Activity session은 저장 op를 작성자·5분 간격으로 묶는 표시 단위다(`activitySessions.ts:40–43,80–107`). session rollback 실행 기능은 없고 README도 미구현임을 명시한다(`README.md:170`). `sessionRestore.ts`는 앱 재시작 시 마지막 폴더/감시 상태 복구이며 과거 작업 되돌리기가 아니다.

## 새 구조에서 추가로 검증할 UI 계약

- 서버/프로젝트/참가 attempt별 epoch를 사용한다. 파일 읽기에 있는 requestId(`FilesView.tsx:205–218`)는 유용한 선례지만 전체 참가·전환 수명주기를 대신하지 않는다.
- 로컬 영속 저장, 전송 대기, 서버 durable ACK, 실제 파일 반영, 팀원 확인을 각각 표시한다. 기존 “Saved”, “Connected”, “Download success” 문구를 새 의미로 그대로 확대하지 않는다.
- 권한은 서버가 결정한다. renderer의 readOnly 또는 버튼 상태만으로 Viewer 보호를 완료했다고 판단하지 않는다.
- 실제 현재 편집 상태는 해당 문서에 붙은 client awareness와 만료 시각으로 표시한다. 명시적 edit claim, 최근 수정자, 접속자는 별도 항목이다.
- 분리된 데모와 실제 사용자 화면에는 같은 완료 상태를 사용하지 않는다. 미구현 기능은 정상 완료 버튼으로 제공하지 않는다.
- 본 문서의 대응표는 전체 목표를 추적하는 목록이다. 새 앱의 각 단계 구현·실행 결과는 단계별 테스트 보고서에서 별도로 표시해야 한다.

## 조사 범위와 제한

직접 읽은 핵심 파일: `src/App.tsx`, `src/components/views/*`의 실제 화면 구현, `ConflictDialog.tsx`, `SettingsDialog.tsx`, `FileTree.tsx`, `ExportPRDialog.tsx`, `ActivitySessionRow.tsx`, `OpDiffDialog.tsx`, `src/store/appStore.ts`, `src/lib/{collaboration,activitySessions,sessionRestore,teamJoin,teamHealth,simulationCapabilities,demoWorkspace}.ts`, `src/i18n/{index,locales}.ts`, `electron/preload.ts`와 해당 API의 `electron/main.ts` 일부. watcher/sync/oplog/checkpoint/conflict/trash/ignore/git의 저장 보장은 별도 코어 조사와 함께 판단해야 한다. 기존 테스트 파일의 존재나 PR 검증 설명만으로 이번 실행 검증을 통과했다고 간주하지 않았다.
