# 두 기기 LAN 최종 확인

이 문서는 **미실시한 실기기 시험 절차**입니다. 한 PC의 여러 프로세스 시험 결과로 대체하지 않습니다. 일반 파일·계정·프로젝트와 분리된 시험 폴더를 사용하세요. macOS 설치·서명·공증 상태는 [사용 설명서](user-guide.md#macos-빌드와-시험--미검증미서명)를 먼저 확인합니다.

1. A와 B를 같은 Wi-Fi/LAN에 연결합니다. A에 작은 UTF-8 LF 파일, CRLF 파일, PNG 등 바이너리와 `.env` 시험 파일이 든 새 폴더를 준비합니다. `.env`에는 실제 비밀 대신 시험 문자열만 넣습니다. B는 빈 수신 폴더를 준비합니다.
2. A에서 폴더를 열고 **팀 → 팀 만들기 → 초대 정보 복사**를 실행합니다. LAN 주소를 확인하고 신뢰하는 경로로 B에게 전달합니다. OS가 묻는 경우 이 앱의 사설 네트워크 통신만 허용합니다. 공유기 포트 포워딩이나 방화벽 전체 해제는 필요하지 않습니다.
3. B에서 **팀 참가**를 열고 초대·수신 폴더를 선택합니다. 초대의 fingerprint를 A와 비교합니다. 근처 팀 검색을 확인한 뒤, 검색이 안 되면 고급 연결의 실제 LAN 주소로 직접 연결합니다. 연결됨과 다운로드/폴더 반영 완료를 구분합니다.
4. 양쪽에서 같은 파일의 같은 위치와 서로 다른 파일에 입력합니다. 본인 Undo/Redo, 실제 OS 한국어·중문 IME의 조합/확정, 붙여넣기, CRLF Enter를 시험합니다. 상대방 이름·커서·선택이 보이고 다른 사람의 입력이 본인 Undo로 사라지지 않는지 확인합니다.
5. 파일·하위 폴더 생성, 이동, 이름 변경, 삭제를 수행합니다. 열지 않은 파일과 바이너리도 B의 실제 디스크에 반영되는지 확인합니다. `.env`, 제외 폴더와 내부 `.cairn-next` 자료가 일반 공유 파일 목록에 나타나지 않아야 합니다.
6. 외부 편집기를 열고 저장한 변경을 확인합니다. 외부 작업 의도를 만들면 해당 사용자 폴더의 원격 반영이 보류되는지, 완료 후 재검사하는지 확인합니다. 오래된 외부 버퍼와 원격 수정이 겹치면 양쪽 버전이 보존되고 검토할 수 있어야 합니다. 미저장 외부 버퍼를 앱이 알고 있다고 가정하지 않습니다.
7. 텍스트 충돌을 비교하고 병합/양쪽 보존을 실행합니다. 바이너리는 크기·해시를 비교하고 양쪽 보존을 선택합니다. 다른 기기에도 결과가 반영되어야 합니다. 이름 있는 체크포인트를 만들고 파일별 복원과 삭제 파일 복원을 시험합니다.
8. B를 오프라인으로 둔 채 편집한 뒤 A에서 과거 체크포인트를 복원합니다. B가 돌아왔을 때 오래된 편집이 현재 파일을 조용히 되살리거나 덮어쓰지 않고 복구 대상으로 남는지 확인합니다.
9. A의 창을 완전히 닫습니다. B는 연결 중단을 알리고 로컬 편집을 보존해야 합니다. B도 종료/재시작한 뒤 A에서 같은 프로젝트를 다시 열고 재연결합니다. 대기 편집·파일·활동·복구 기록을 확인합니다. 초대가 만료됐다면 A에서 기존 멤버를 선택해 갱신한 초대를 B가 같은 작업 사본에 사용합니다.
10. 양쪽을 정상 종료한 뒤 파일 목록과 SHA-256을 비교합니다. Windows는 `Get-FileHash -Algorithm SHA256 <파일>`, macOS는 `shasum -a 256 <파일>`을 사용할 수 있습니다. 원본 LF/CRLF, 바이너리 해시, 충돌 사본, 복구 자료와 내부 DB가 보존되는지 확인합니다. 실행 중 DB/WAL 파일은 삭제하거나 교체하지 않습니다.

기록할 내용: 두 기기의 OS/CPU, 설치 파일 SHA-256, 앱 버전, Wi-Fi 환경, 각 단계 결과, 실제 파일 해시, 연결/재시작 시간, 실패 시 진단 오류 코드. 새 기기에 전달한 스냅샷 ZIP은 일반 파일 사본이며 원래 동기화 작업 폴더와 구분합니다.
