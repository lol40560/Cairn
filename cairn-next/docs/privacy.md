# Cairn Next 0.2.0-rc.1 · 개인정보와 데이터 처리

이 문서는 비공개 로컬/LAN 릴리스 후보의 구현상 데이터 흐름을 설명합니다. 호스팅 서비스 약관이나 특정 법률의 준수 인증이 아닙니다. 사용자 프로젝트를 자동으로 공개 저장소나 중앙 서비스에 업로드하는 기본 동작은 없습니다.

## 저장하는 정보

| 정보                                            | 저장·사용 목적                                                   |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| 프로젝트 파일과 경로                            | 로컬 편집, 팀 파일 동기화, 디스크 반영                           |
| 파일별 ID·내용 해시·공동 편집 상태              | 같은 파일의 변경 추적, 내용 검증, 동시 편집과 재접속             |
| 변경 전후 버전·활동·체크포인트·충돌·삭제 기록   | 변경 비교와 사용자가 선택한 복구                                 |
| 표시 이름·멤버/클라이언트 ID·역할·선언한 출처   | 작성자 표시, 권한 검사, 활동과 claim 표시                        |
| 최근 프로젝트 경로·화면 언어·환경설정           | 재실행과 프로젝트 탐색                                           |
| 팀 식별자·TLS 인증서/개인 키·초대 토큰 해시     | 팀 인증, 인증서 고정 검증, 초대 만료·폐기                        |
| 다시 연결할 초대, 선택적으로 저장한 GitHub 토큰 | 사용자가 요청한 연결과 내보내기; 앱 프로필의 OS 암호화 보관 사용 |

실제 파일·불변 버전·복구 DB는 일반 로컬 데이터입니다. 전체 프로젝트 저장소를 암호화하는 기능은 없습니다. OS 계정 권한·디스크 암호화·백업 보호는 별도로 관리해야 합니다.

프로젝트 기록은 작업 폴더의 `.cairn-next/project.sqlite`와 관련 파일에, 호스트의 팀 인증자료는 `.cairn-next/team.sqlite`에 저장됩니다. 디스크 반영의 보호 사본은 `.cairn-next/recovery` 또는 `.cairn-next/replica-recovery`에 남을 수 있습니다. 생성자의 내부 편집 사본은 앱 사용자 데이터의 `owner-workcopies/<projectId>/` 아래에 있습니다.

앱 사용자 데이터의 `profile.json`에는 비밀값이 아닌 설정·최근 프로젝트·선택 상태·팀 포트·GitHub 저장소 대상이 저장됩니다. `secrets.encrypted`는 OS 보안 저장소로 암호화된 접근 자료입니다. `profile.json`도 개인 경로·프로젝트 이름 같은 정보를 포함하므로 공개 문서가 아닙니다. 실제 경로와 백업 절차는 [사용 설명서](user-guide.md#저장-위치와-백업)를 참고하세요.

## 연결별로 전달되는 정보

### 로컬 프로젝트

로컬 편집은 PC 내부 loopback WSS 연결을 사용합니다. **팀 만들기**를 실행하기 전에는 해당 프로젝트의 WSS 수신기가 LAN 인터페이스에 열리지 않습니다. 외부 계정이나 유료 API를 기본 실행에 사용하지 않습니다.

### LAN 팀

팀을 만들면 해당 PC의 LAN 연결을 통해 승인된 참가자에게 현재 파일, 동기화에 필요한 버전·공동 편집 상태, 공유된 활동·claim·충돌·체크포인트·삭제 기록이 전달됩니다. 열람자도 허용된 공유 내용을 읽어 로컬에 저장할 수 있습니다. 참가자에게 읽기 권한을 주는 것은 해당 내용의 사본을 받을 수 있게 하는 것입니다.

WSS/TLS와 초대의 인증서 고정값으로 전송·상대 신원을 검증합니다. 기준 프로젝트를 보관하는 호스트와 승인된 클라이언트는 내용을 읽을 수 있습니다. 호스트에게도 숨기는 종단간 암호화나 서버 없는 협업을 제공하지 않습니다.

근처 팀 검색은 mDNS로 공개 팀 이름·식별자·주소·포트·인증서 fingerprint 같은 연결 단서를 같은 네트워크에 알립니다. 검색 광고에 초대 토큰이나 프로젝트 파일 내용은 넣지 않습니다. 팀 이름 자체는 같은 네트워크에 보일 수 있으므로 민감한 내용을 이름으로 사용하지 않는 것이 좋습니다. 검색 결과만으로 인증하지 않으며 직접 초대 연결도 가능합니다.

### GitHub 내보내기

GitHub 설정·미리보기·게시를 사용하면 사용자가 지정한 저장소에 대해 `https://api.github.com`으로 HTTPS 요청을 보냅니다. 미리보기는 저장소 기준·트리·필요한 파일 내용을 읽습니다. 명시적 게시 후에만 선택 파일의 바이트·경로, 커밋/PR 제목·설명, 새 브랜치 정보가 GitHub에 전달됩니다. 인증 토큰은 API 요청 헤더에 사용합니다.

선택하지 않은 원격 파일은 변경하지 않습니다. 원격 삭제 후보는 기본적으로 선택되지 않습니다. 게시 실패 시 새 브랜치·커밋이 GitHub에 남아 복구에 사용될 수 있습니다. 앱에서 토큰을 지우거나 프로젝트를 닫아도 이미 GitHub에 만들어진 브랜치·PR·Git 객체를 삭제하지 않습니다. 이후 GitHub 쪽 보관과 접근은 해당 저장소·계정 정책의 영향을 받습니다.

### 기타 외부 서비스

Cairn 프로젝트 모듈에는 광고, 분석 SDK, 자동 오류 업로드, AI 추론 호출 또는 중앙 클라우드 파일 저장 기능을 넣지 않습니다. “AI로 선언됨”은 사용자가 입력한 출처 표시이며 자동 AI 판별이나 AI 업체 인증이 아닙니다. 사용자가 외부 편집기·AI 도구·클라우드 백업 폴더를 따로 사용하는 경우 해당 도구의 전송은 이 앱의 통제 범위 밖입니다.

개발용 의존성 설치·패키징은 npm/Electron 등 배포 서버에 연결될 수 있습니다. 이는 설치된 앱의 프로젝트 동기화와 다른 개발 과정입니다. 이번 후보에서 실제 수행한 네트워크·플랫폼 검증 범위는 시험 문서를 확인하세요.

## 비밀정보 처리

초대에는 접근 토큰이 들어 있습니다. 신뢰하는 경로로만 전달하고 공개 이슈·스크린샷·저장소에 넣지 마세요. 클립보드 복사는 명시적으로 실행하며, 이후 클립보드는 OS와 다른 앱에서도 읽힐 수 있습니다. 초대 해시는 호스트 인증 DB에 저장되지만 초대 원문이나 재연결 자료를 가진 사람은 유효기간과 권한 범위에서 접속할 수 있습니다.

저장하는 GitHub 토큰과 재연결 초대는 Electron의 OS 보안 저장소를 사용해 암호화한 앱 프로필 자료로 처리합니다. 안전한 암호화가 불가능할 때 평문으로 대체 저장하지 않습니다. 다른 PC·OS 계정으로 복사하면 복호화할 수 없을 수 있습니다. 프로젝트 DB·스냅샷 ZIP·GitHub preview receipt에 GitHub 토큰을 넣지 않습니다.

`.env` 계열·키·인증정보·내부 DB·의존성/빌드 폴더 같은 기본 제외 규칙을 공유와 내보내기에도 다시 적용합니다. 이 규칙은 파일명·경로를 바탕으로 하며, 일반 파일 안에 숨겨진 모든 비밀정보를 검출하는 검사기는 아닙니다. 공유 전 검토가 필요합니다.

## 기록의 유지와 삭제 범위

- **최근 목록에서 제거**: 목록 참조만 제거합니다. 프로젝트 폴더와 기록은 남습니다.
- **팀 멤버 권한 폐기**: 이후 인증·변경 요청을 막습니다. 이미 받은 사본이나 외부 백업을 지우지 않습니다.
- **파일 삭제**: 현재 프로젝트에서 삭제하고 복구 항목을 보관합니다. 다른 연결된 참가자에게도 해당 변경이 전달됩니다.
- **삭제된 항목 비우기/보관기간 만료**: 해당 복구 목록을 제거합니다. 별도 체크포인트와 다른 기록·불변 blob까지 안전하게 지우는 기능은 아닙니다.
- **체크포인트 삭제**: 선택한 체크포인트 기록을 제거합니다. 모든 과거 버전의 디스크 흔적을 지운다고 보장하지 않습니다.
- **GitHub 토큰 지우기**: 앱이 보관한 해당 토큰을 제거합니다. GitHub에서 토큰 자체를 폐기하거나 이미 생성한 PR을 삭제하지 않습니다.
- **앱 제거**: 설치 파일을 제거합니다. 별도로 선택한 프로젝트 폴더를 삭제하지 않으며, Windows 설치 설정은 앱 사용자 데이터 자동 삭제를 끕니다.

기본 삭제 항목 보관기간은 30일이며 소유자가 조정할 수 있습니다. 그 외 작업 기록·불변 버전·복구 자료는 디스크 사용량을 늘릴 수 있습니다. 현재 내용의 크기 제한은 전체 과거 기록 용량 한도가 아닙니다. 내부 DB를 수동 편집하거나 실행 중 WAL 파일을 지워 용량을 확보하지 마세요.

## 진단과 검증 자료

진단 정보 복사는 사용자가 요청할 때 앱·런타임 버전, 시각, 연결 상태, 처리 대기 수, 파일 ID별 반영 상태, 오류 코드 등을 클립보드에 담습니다. 현재 진단 payload에는 작업 폴더의 전체 경로·토큰·개인 키를 넣지 않습니다. 활동 요약에는 경로·작성자 이름 같은 정보가 포함될 수 있으므로 공유 전에 내용을 확인하세요. 토큰과 개인 키는 오류 메시지로 출력하지 않도록 처리합니다.

자동 시험은 별도의 임시 프로젝트·앱 프로필과 로컬 GitHub 모의 서버를 사용합니다. 화면 캡처·시험 로그·내보낸 ZIP 등 검증 결과물도 프로젝트 내용을 포함할 수 있으므로 실제 개인 프로젝트로 시험하지 않습니다. 이 후보 문서 작성이나 테스트가 공개 업로드를 승인하는 것은 아닙니다.

## 권한과 서비스의 한계

작성자는 자신의 표시 이름을 설정할 수 있고, 명시한 AI/외부 출처는 자기 신고입니다. 이 앱은 실명·회사 계정 신원이나 외부 도구의 무결성을 인증하지 않습니다. LAN 연결을 허용할 때는 신뢰하는 프로젝트 참여자에게 필요한 최소 권한을 부여하세요.

정상 종료는 이 앱의 연결과 호스팅을 종료합니다. 항상 실행되는 백그라운드 서비스·원격 삭제 서비스·프로젝트 보관 클라우드가 아닙니다. 더 자세한 사용·복구 절차는 [사용 설명서](user-guide.md), 의존성 고지는 [제3자 고지문](../THIRD_PARTY_NOTICES.md)을 확인하세요.
