# Cairn Next module API

This document describes the project modules used by 0.2.0-rc.2. Types are in `shared/project.ts`; paths below are relative to `cairn-next/`. `core/common.ts` supplies hash/b64/unb64/CairnError/openDb/transaction/readBounded/writeDurable/acquireOwnership. `core/project/filesystem.ts` supplies the shared path/ignore policy and protected filesystem writer.

## ProjectStore — `core/project/store.ts`

`new ProjectStore({root,mode:'authority'|'replica',name?,projectId?,ownerId?,autoProject?:boolean})` synchronous import/open. Own metadata `.cairn-next/project.sqlite`, process lease same metadata root, old `.cairn` rejected; original phase-one DB retained, never overwritten. `db: DatabaseSync`, `root`, `dataDir`, `projectId`, `ownerId`, `policy:ProjectPolicy` public readonly. Extends EventEmitter. Authority initial scan imports supported current files into immutable blobs and catalog, with Yjs identity generated once and persisted; existing files are baseline and not rewritten.

- `status():ProjectStatus`, `files(includeDeleted?:boolean):ProjectFile[]`, `file(id):ProjectFile|undefined`, `revision():number`, `manifestHash():string`.
- `putBlob(bytes:Uint8Array):string`, `getBlob(hash):Uint8Array`, `hasBlob(hash):boolean` (all validate hash/size), `blobSize(hash):number`.
- `apply(command:ProjectCommand,actor:Actor):ProjectEvent`: authority only, opId+payload hash+actor dedup. Validate permission/path/generation/CAS. Single transaction contains blobs/files/metadata/activity/journal; ACK caller only after return. No filesystem writes inside transaction. Emits `change` only after COMMIT. Revision monotonic. After commit invokes projection queue unless autoProject false. Handlers use staged mutations below.
- `registerCommand(kind,handler:(command:ProjectCommand,actor:Actor)=>Record<string,unknown>|void):void`. Handler runs INSIDE apply transaction; no nested COMMIT, emit or direct disk write. Store owns dispatch for text/write/create/move/delete/rescan; recovery feature owns other kinds.
- `stageFile(file:ProjectFile,preserveDisk?:boolean):void` requires active command transaction, records before/after and uses current next revision. `nextRevision():number` valid inside handler. `newFileId():string` UUID. `textFile(file,text,bumpGeneration:boolean):ProjectFile` stores valid text/Yjs state/content blobs; bump replaces CRDT doc identity but keeps stable fileId. For existing document safe external writes use minimal diff on original Y.Doc, not full reset.
- `setMetadataProvider(fn:()=>SharedMetadata):void`, `metadata():SharedMetadata`. Defaults empty metadata until RecoveryService installed.
- `snapshot():SnapshotManifest` includes current live supported catalog at revision R, referenced content+state blob descriptors, metadata, digest. Immutable blobs/journal retained so concurrent download catches up.
- `eventsSince(revision,limit=256):ProjectEvent[]`, `query(query:StoreQuery):unknown`; query hooks for recovery permitted via `registerQuery(kind,fn)`. Query activity and delete preview owned by store.
- Outgoing event/snapshot JSON is limited to 20 MiB, leaving room below the transport frame cap. Atomic writes that exceed the event or future snapshot limit fail with `OPERATION_TOO_LARGE` before COMMIT. History/activity pages use bounded SQLite iteration and return intact records; callers continue from the last delivered revision.
- `installSnapshot(snapshot,blobs:BlobObject[],afterInstall?:()=>void):void`, `ingest(event,blobs:BlobObject[],afterInstall?:()=>void):void`: replica canonical catalog installation, verify hashes/ordered revisions/manifest; NO projection auto for replica. `installSnapshot` accepts cached verified blobs via putBlob, rejects foreign project identity or uninspected existing destination. Replica merges local outbox state separately.
- `projectPending():void`, `retryProjection():void`; authority only actual folder writer. Records expected previous hash/path and desired record; FS failures stay pending/blocked with content recoverable. Claims may hold external owner's projections via `setProjectionHold(fn:(fileId)=>boolean)`.
- `startWatching():void`, `stopWatching():void`, `scanExternal(actor?:Actor):void`; baseline current bytes/hash/revision retained separately, stale external writes create conflict via registered handler. External safe text diff preserves unchanged Yjs IDs. Initial imported bytes are safe baseline. Internal/remote projection does not advance external read baseline. `adoptExternalBaseline(fileId):void` for explicit claim.
- `close():void` stops watcher/timers, closes DB and lease (callbacks check closed).

`new RecoveryService(store)` from recovery.ts installs command/query/metadata providers. Main, host and tests create it immediately after store. Store must not statically depend on recovery (avoids cycle and independent testing). Store external watcher may queue conflict if no handler registered until service installed; tests using watcher must install it.

## RecoveryService — `core/project/recovery.ts`

Constructor creates its tables via store.db and registers handlers/queries. Owns claims, conflicts, checkpoints, trash, settings. `store.setDeleteObserver(fn:(files:ProjectFile[],actor:Actor)=>void)` runs in the apply transaction; the service uses it to insert trash entries. Metadata carries full current shared records (bounded). Replica ingest calls service `installMetadata(metadata):void`, registered via `store.setMetadataInstaller(fn)`; it runs in the same ingest transaction. No extra ACKs/events.

Checkpoint restore checks expected global revision, creates protective checkpoint and stages restored/deleted files in SAME command transaction; generations bump. Conflict resolution keeps before/local/remote blobs, expected revision check, own/remote/both/merged. Binary only local/remote/both. Claim author is authenticated actor; owner may cancel stale claims; expiry system action only internal actor. Strict claim rejection in Store via `setWriteGuard(fn:(fileId,actor,command)=>void)`; default multi-user text remains allowed. Settings affect policy and retention; ignored paths unshare preserving disk rather than delete.

## TeamHost — `core/project/transport.ts`

`static async start({store:ProjectStore,name:string,port?:number,lan?:boolean}):Promise<TeamHost>`. Reuses pinned TLS/WSS/auth/heartbeat patterns from old core/server.ts; internal session only, not public headless product. API `status():TeamStatus`, `invite(role:Role,address?:string,ttlMs?:number):TeamInvite`, `setLan(enabled:boolean):Promise<void>` (may rebind preserving identity/token grants), `revoke(memberId):void`, `stop():Promise<void>`. Emits `status`; owns no second store/FS watcher. Owner invitation memberId equals store.ownerId so claims align. All RPC permissions checked each time. Transport validates commands and calls store.apply, then sends durable ack + committed event. Query/manifest/blob/changes require auth. Blobs chunked on download; commands <=24MiB for <=16MiB binary payload. Supports snapshot journal catch-up and barrier manifests. Exposes RPC client helper `TeamConnection` for replica (below); it owns nonce heartbeat and reconnect is replica responsibility.

`TeamConnection` constructor({invite:TeamInvite,clientId:string,name:string}); async `connect():Promise<{role:Role;status:TeamStatus}>`; `request<T>(method:string,args:unknown):Promise<T>`; `close():void`; `sendApplied({revision,manifestHash,projection}):void`; `awareness({fileId,generation,update}):void`. Extends EventEmitter: `event` ProjectEvent, `status` TeamStatus, `awareness` envelope, `disconnect` safe error. Each attempt guarded. RPC names: snapshot→SnapshotManifest; blob({hash,offset,length})→{hash,offset,total,data}; events({after,limit})→ProjectEvent[]; barrier→{revision,manifestHash}; command({command})→ProjectEvent; query({query})→unknown; members→public members; revoke({memberId}) Owner. Server never emits raw secrets in errors.

`parseTeamInvite(string):TeamInvite` validates schema, WSS route `/team`, PEM/fingerprint/identity/expiry. Discovery separate exports `class TeamDiscovery { start():void; list():DiscoveredTeam[]; advertise(status, fingerprint):void; stopAdvertising():void; close():void; }` EventEmitter update. Network discovery never supplies auth and is not required by direct connection.

## ProjectReplica — `core/project/replica.ts`

`new ProjectReplica({root:string,invite:TeamInvite,name:string,watch?:boolean})`; uses ProjectStore mode replica + RecoveryService; share ONE db for canonical rows/local_docs/outbox/receipts. `store` readonly. `connect():Promise<void>` performs auth→manifest download/cache/verify→install R→catch-up→barrier→project→ready. `disconnect():void`, `cancel():void`, `close():void`, `status():ReplicaStatus`, `select(fileId):void`, `editorSnapshot(fileId):ClientSnapshot` compatible with existing Editor. `applyLocalUpdate(fileId,generation,update:Uint8Array):ClientSnapshot` commits local Yjs+outbox first; source app by default. `command(input:CommandInput):Promise<ProjectEvent>` persists command before transfer; structural/restore operations only online (local creator has loopback connection). `query(query):Promise<unknown>`, `blob(hash):Promise<Uint8Array>`, `snapshot():Promise<SnapshotManifest>`, `retryProjection():void`, `setWatching(enabled):void`, `setSource(source:ChangeSource):void`, `awareness(envelope):void`. Events `state` ReplicaStatus, `awareness` envelope.

No replica initializes from plain text after first creation. Metadata/structural broadcasts update closed files too. Merge local CRDT state with server state only same generation. Higher generation/deletion preserves rejected outbox/local bytes into local conflicts before replacing view; never hidden resurrection. Local conflicts reside in same DB/recovery and are included status metadata; resolve may submit to authority after explicit review. Disk scan uses policy + baseline; safe external saves become CAS write commands, stale/offline structure becomes conflict. External claim blocks this client's remote projection until release; avoid sending repeated conflict ops for same observed hash. Every peer confirmation requires no pending/rejected/conflicts, verified manifest and all local projections applied.

`setName(name):Promise<void>` updates validated profile names and reconnects the same member/client only when a connection was desired; explicit offline remains offline. `editorSnapshot(fileId,precomputedStatus?)` can reuse the same caller-computed status. Transfer progress publications are capped at 10 Hz; stage transitions and durable edits are immediate. Failed non-draft command intentions are retained in `command_failures` and removed from the active outbox so fresh review/retry can succeed. New failed merge/conflict uploads preserve their bytes as independently reviewable local drafts before archival; ordinary text/write/create drafts remain recoverable until explicit review.

## Exports — `core/project/exports.ts`

Independent exported async `exportSnapshot({snapshot,readBlob,outputPath}):Promise<{path,files,bytes}>` writes validated ZIP with manifest (no app DB/token/history) to a NEW output path; preserves source and consistent snapshot revision. readBlob(hash) async callback, reverify bytes/hash and portable paths; same policy has already filtered manifest but hard-block secrets/internal defaults again. `previewGitHub({snapshot,readBlob,owner,repo,baseBranch,token,apiBase?}):Promise<GitHubPreview>` and `publishGitHub({preview,readBlob,token,title,body,apiBase?}):Promise<{url,branch}>`. Preview contains baseHead SHA, selected changed file records and diff/content hash; explicit file selection. Publish rechecks remote base SHA and selected hashes before uploading, new branch collision-safe, creates PR only user action. No changes to existing repository settings. apiBase only loopback for tests or exact https://api.github.com in production. Token memory only; main safeStorage owns persistence.

## UI bridge

`shared/release-api.ts` defines the implemented `ReleaseApi` and renderer state types. `electron/main.ts`, `electron/controller.ts` and `electron/preload.cts` provide lifecycle, command handling and the restricted renderer bridge. `ui/main.tsx`, the Editor adapter, views, styles and i18n dictionaries consume that API. No user-facing PC hosting form, headless action or tray hosting is exposed; the PC server card is informational Coming Soon content.

The optional third `afterInstall` callback in `installSnapshot`/`ingest` runs inside the same database transaction for replica local-state/outbox reconciliation. `ProjectStore.configurePolicy(policy):ProjectPolicy` wires the current canonical `.gitignore` resolver onto a candidate policy for recovery settings/restore decisions.
